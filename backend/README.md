# Backend

La API HTTP existente (`server.py`) conserva el arranque compatible con Docker. La lógica nueva de administración usa `admin.py` y el módulo de usuarios integrado en SQLite: `app_users` guarda el PIN hash, `employee_number` y `assignment_id`. `config.py` carga el entorno en una estructura centralizada; `auth.py` centraliza el login por PIN, las sesiones y la validación de Mini App de Telegram; `access.py` centraliza la relación usuario-empleado ERP y el filtrado de tareas/proyectos por `responsibleAssignmentId` o `employeeNumber`; `audit.py` centraliza la bitácora de acciones y su persistencia; `health.py` diagnostica SQLite y la configuración mínima de ERP/Telegram sin exponer secretos; `database.py` concentra el esquema, migraciones ligeras, recuperación de operaciones interrumpidas y catálogo demo; `erp.py` centraliza el catálogo ERP, responsables y transporte de proyectos/tareas; `telegram.py` centraliza la Bot API, fotos, grupos de medios y límites de texto; `delivery.py` procesa la cola persistente y sus estados de publicación; `reports.py` valida, relaciona y registra reportes con control de avance e idempotencia; `validation.py` concentra las reglas de detalles de campo, paros, maquinaria, evidencias y formato del mensaje; `media.py` valida y almacena evidencias privadas; `employees.py` administra empleados, roles, versiones y cuadrillas; `security.py` centraliza el hash/verificación de PIN y `http_client.py` centraliza las llamadas JSON. Esta carpeta es el destino de la extracción progresiva de adaptadores, autenticación y repositorios sin interrumpir la operación actual.
